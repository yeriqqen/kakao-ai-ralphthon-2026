# YOKOBU · 3분 발표와 병원 문의 시연

**발표는 한국어, 고객 화면은 영어. 친구의 OpenAI 키가 설정된 노트북에서 실행합니다.**

## 지금 준비할 것

1. 친구의 작업 중인 변경을 먼저 커밋합니다. 아래 브랜치를 가져옵니다. 키가 들어 있는 `.env`는 커밋하지 않습니다.

   ```sh
   git fetch origin
   git switch feat/v2-design-integration
   git pull --ff-only
   npm start
   ```

2. 원래 서버가 실행 중이면 그 터미널에서 종료한 뒤 다시 시작합니다. 기본 주소는 `http://localhost:4173`입니다. 로컬 `.env`의 `OPENAI_API_KEY`가 필요합니다. 채팅에 키를 붙여 넣지 않습니다.
3. 고객 탭과 그 탭의 **Open business tab** 링크를 준비합니다. 발표자는 고객과 설명, 친구는 가상 병원 접수 담당자를 맡습니다. 사업자 탭은 고객 동의 전에는 통화를 시작하지 않습니다.
4. 아래 요청으로 질문 계획까지만 준비해 두세요. 고객 요청과 계획은 화면에 남겨 둡니다. 발표 중 동의하고 통화를 수락합니다.
5. 본 발표 전에 한 번 끝까지 실행합니다. **한국어 소리 → 추가 질문 → 고객 답변 전달 → 복창 확인 → 종료 → 마이크 해제 → 요약**을 직접 확인합니다. 최신 종료 수정은 모의 이벤트로 검증했으며, 이번 실제 음성 리허설은 아직 완료하지 않았습니다.
6. 발표 파일과 PDF를 미리 열어 두세요. 화면 예시는 준비된 시뮬레이션이며 실제 통화 성공 기록이 아닙니다.

## 3분 발표 원고

### 0:00–0:20 · 1번 슬라이드

안녕하세요. 저희는 한국어 전화가 어려운 외국인이 자기 언어로 필요한 도움을 요청할 수 있는 **YOKOBU**를 만들었습니다. 사용자는 채팅하고, AI가 한국어로 문의한 뒤 결과를 정리합니다. 오늘은 병원 문의 한 흐름을 보여드리겠습니다.

### 0:20–0:40 · 2번 슬라이드

병원에 전화해 시간과 비용을 묻는 일도, 언어가 다르면 어렵습니다. 문장 번역만으로는 상대가 다시 묻는 질문에 답하고 결과를 기억해야 합니다. YOKOBU는 문의할 내용을 정리하고, 추가 질문을 고객에게 되묻고, 확인된 결과까지 연결합니다. 오늘은 팀원이 접수 담당자를 맡는 시뮬레이션입니다.

### 0:40–2:00 · 3번 슬라이드 → 앱

“고객은 내일 오후 진료 시간과 비용을 물었습니다. 이 계획을 확인하고 문의를 허용합니다.”

**고객 동의 → 사업자 수락. AI의 한국어 첫 인사를 들은 뒤 접수 담당자가 응답합니다.**

“병원에서 고객에 대한 추가 정보를 물으면, AI가 추측하지 않고 채팅으로 돌아옵니다.”

**고객에게 전달된 질문에 영어로 짧게 답합니다. 한국어로 전달되는 것을 듣습니다.**

“필요한 답을 확인하고, 마지막으로 복창한 내용에 동의를 받으면 통화를 마칩니다.”

**복창이 정확한 경우에만 접수 담당자가 확인합니다. 종료와 요약을 보여줍니다.**

### 2:00–2:25 · 4번 슬라이드 또는 실제 결과 화면

결과에서는 긴 대화 대신 확인한 답과 다음 행동을 먼저 보여줍니다. 불확실한 비용은 확정 금액으로 바꾸지 않습니다. 세부 기록은 필요할 때 펼쳐볼 수 있습니다. 문의가 완료되면 마이크도 해제합니다. 지금은 예약을 확정하는 기능이 아닌 문의 시뮬레이션입니다.

### 2:25–3:00 · 5번 슬라이드

Codex에는 화면과 통화 상태 흐름을 맡기면서, 모르는 정보는 추측하지 말고 확인된 근거가 없으면 완료하지 말라는 조건을 줬습니다. 저희는 휴대폰 화면과 실제 한국어 대화를 확인했습니다. 확인 응답 뒤 답변이 초기화되던 문제를 재현해 고쳤고, 마지막 인사 뒤에도 연결이 남을 수 있는 문제도 수정했습니다. 최신 수정은 자동 검증했고, 실제 음성은 다시 확인해야 합니다. 한국 생활에서 다음 행동까지 이어주는 도우미, YOKOBU입니다. 감사합니다.

실제 리허설이 성공하면 마지막의 검증 설명을 **“최신 수정도 실제 음성으로 끝까지 확인했습니다.”**로 바꿔도 됩니다. 직접 확인하기 전에는 바꾸지 않습니다.

## 시연 입력과 접수 담당자 대사

모든 인물, 병원, 시간, 금액은 **시연용 가상 정보**입니다. 모델이 만든 실제 필수 질문에 맞춰 답하세요. 화면에 없는 질문이 이미 처리됐다고 가정하지 않습니다.

**고객 첫 입력 — 복사해서 사용**

> I need a non-urgent general consultation at a clinic near Hongdae tomorrow after 2 pm. Please ask what times are available and the consultation cost without Korean medical insurance.

AI가 필요한 정보를 추가로 물으면 짧게 답하세요. 이 요청은 실제 예약 요청이 아니라 시간과 비용 문의입니다.

**접수 담당자 첫 응답**

> 안녕하세요. 가상 홍대의원입니다. 무엇을 도와드릴까요?

**추가 질문 — 아직 모르는 정보 하나만 선택**

> 이번이 첫 방문이신가요?

고객 답변:

> Yes, this is my first visit.

이미 첫 방문 여부를 전달했다면 아래 질문을 대신 사용합니다.

> 고객님께서 여권을 가져오실 수 있나요?

고객 답변:

> Yes, I can bring my passport.

**시간을 물으면**

> 일반 진료 가능합니다. 내일 오후 세 시에 진료받으실 수 있습니다. 아직 예약이 확정된 것은 아닙니다.

**비용을 물으면**

> 한국 건강보험이 없는 경우 상담료는 오만 원입니다. 검사비는 별도입니다.

**다른 질문을 받으면**

가상 접수 담당자로서 명확하게 답하거나 “그 부분은 확인이 필요합니다”라고 말하세요. 미해결 정보를 성공으로 처리하려고 억지로 확인하지 않습니다.

**AI가 정확히 복창한 뒤에만**

> 네, 방금 확인하신 내용이 모두 맞습니다. 감사합니다.

인사가 끝나면 사업자 화면에서 마이크와 연결이 해제되는지 확인합니다. 누락된 마지막 재생 이벤트에도 완료 승인 후 약 8초 이내에 로컬 연결을 정리하는 보호 장치가 있습니다. 이 시간 제한은 미해결 통화를 성공으로 바꾸지 않습니다.

## 지연될 때 발표를 이어가는 문장

음성 연결이나 응답이 길어지면 **End simulation / End call**로 로컬 통화를 끝내고 4번 슬라이드로 넘어갑니다.

> 지금 음성 연결이 지연되어 준비한 화면 예시로 결과 구조를 설명드리겠습니다. 이 화면은 실제 통화 결과가 아닌 시연 예시입니다. 확인된 답과 미해결 내용을 구분하고, 상세 기록은 펼쳐볼 수 있게 만들었습니다.

이미 완료된 것처럼 말하지 않습니다. 발표를 멈추고 디버깅하지 않습니다.

## 예상 질문

- **실제 병원에 전화하나요?** 현재는 OpenAI Realtime과 브라우저 음성을 이용한 가상 통화입니다. 실제 전화망 연결과 병원 검색은 구현 범위에 없습니다.
- **일반 번역과 무엇이 다른가요?** 고객의 목적을 질문으로 정리하고, 모르는 고객 정보는 채팅으로 되묻고, 답변 근거와 완료 상태를 관리합니다.
- **예약도 되나요?** 현재 시연은 가능 시간과 비용 문의입니다. 예약 확정을 주장하지 않습니다.
- **AI가 틀리면요?** 답변의 대화 근거와 복창 확인을 검사합니다. 미해결 내용은 남겨 두며 사용자가 계속하거나 종료할 수 있습니다.
- **사용자 검증은 했나요?** 팀의 UI·API·음성 리허설을 진행했습니다. 실제 대상 사용자의 효용 검증은 아직 하지 않았습니다.

## 확인된 범위

최신 수정 기준 자동 검증: 단위 64, 로컬 HTTP 30, 고객 UI 20, 사업자 UI 19, 디자인 32 — 총 165개. HTTP·브라우저 검사는 실제 OpenAI 음성 통화의 성공 증거가 아닙니다. 기존 실제 한국어 대화는 부분 확인 상태이며 최신 종료 흐름의 실음성 확인은 친구 노트북에서 해야 합니다.
